Semana 23Rotas, modelos e proteção de APIs+

Para que servem as rotas?
A) Direcionar requisições a funcionalidades.

Um middleware pode ser usado para quê?
A) Autenticar requisições.

No Django, os modelos representam o quê?
A) A estrutura dos dados.

Diferencie rota, middleware e tratamento de erros no Express.js.
A rota direciona as requisições para uma funcionalidade. O middleware realiza verificações, como autenticação. Já o tratamento de erros organiza as mensagens de erro e evita expor informações sensíveis.

Explique a relação entre modelos e templates no Django.
Os modelos organizam e representam os dados do sistema, enquanto os templates são responsáveis pela apresentação dessas informações nas páginas.

Cite duas ameaças à segurança web mencionadas no texto e uma proteção pertinente.
Duas ameaças são SQL Injection e XSS. Uma proteção é validar e verificar as entradas dos usuários para evitar ataques.

Uma API financeira permite consultar transações sem autenticação e mostra erros internos completos. Identifique os problemas e proponha soluções.
Os problemas são a falta de autenticação, que permite que pessoas não autorizadas consultem as transações, e a exposição de erros internos, que pode revelar informações importantes do sistema. Para resolver, é necessário implementar autenticação nas requisições e padronizar as mensagens de erro, evitando mostrar informações internas aos usuários.

Semana 24Autenticação, autorização e logs+

O HTTPS protege principalmente o quê?
A) O tráfego entre cliente e servidor.

O que significa hardening?
A) Reduzir vulnerabilidades e serviços desnecessários.

O que a autorização determina?
A) O que um usuário pode acessar.

Diferencie autenticação e autorização com um exemplo.
Autenticação verifica a identidade do usuário, enquanto autorização define o que ele pode acessar. Por exemplo, fazer login é autenticação, e ter permissão para acessar determinada área é autorização.

Por que firewall e HTTPS devem ser usados em conjunto?
Porque o firewall controla as conexões permitidas e o HTTPS protege a comunicação entre o cliente e o servidor. Juntos, aumentam a segurança do sistema.

Explique a utilidade de logs e alertas na resposta a incidentes.
Os logs registram as atividades do sistema e os alertas avisam sobre possíveis ameaças, ajudando a identificar problemas e investigar incidentes.

Uma API registra tentativas repetidas de acesso e aceita conexões HTTP. Descreva quatro medidas prioritárias.
Ativar HTTPS para proteger a comunicação. Configurar um firewall para controlar as conexões. Implementar autenticação e autorização para impedir acessos não permitidos. Monitorar os logs e configurar alertas para identificar tentativas suspeitas de acesso.

Semana 25OAuth e auditoria+

Qual é a finalidade central do OAuth?
A) Delegar autorização sem compartilhar senha.

Qual fluxo é voltado à comunicação entre servidores?
A) Client Credentials.

Qual ferramenta é citada para análise centralizada de logs?
A) ELK Stack.

Explique a função dos escopos no OAuth.
Os escopos definem quais permissões uma aplicação terá, limitando o acesso apenas aos recursos necessários.

Por que é necessário definir expiração e renovação de tokens?
Para aumentar a segurança, evitando que tokens antigos sejam utilizados por muito tempo e permitindo renovar o acesso quando necessário.

Quais eventos devem ser registrados nos logs de uma API e por quê?
Devem ser registrados acessos, erros e operações importantes, pois essas informações ajudam a identificar problemas e investigar atividades suspeitas.

Uma API financeira registra repetidas tentativas de acesso negado. Proponha um plano breve de auditoria e indique como o OAuth poderia limitar permissões.
Primeiro, é necessário analisar os logs para identificar as tentativas de acesso negado e verificar possíveis atividades suspeitas. Também é importante configurar alertas e manter os registros organizados. O OAuth pode limitar as permissões por meio dos escopos, permitindo que cada aplicação acesse somente os recursos necessários.

Semana 26Backups, atualizações e incidentes+

O backup diferencial copia o quê?
A) Alterações desde o último backup completo.

Antes de aplicar patches em produção, recomenda-se o quê?
A) Testar em homologação.

Qual ação integra um plano de resposta?
A) Contenção do incidente.

Compare backup completo, incremental e diferencial.
O backup completo copia todos os dados. O incremental copia apenas as mudanças desde o último backup. Já o diferencial copia as alterações desde o último backup completo.

Por que testar a restauração é tão importante quanto realizar backups?
Porque garante que os dados podem ser recuperados corretamente caso aconteça algum problema ou perda de informações.

Descreva as primeiras etapas de resposta a um ataque DDoS.
Primeiro, é necessário identificar o ataque, depois conter o problema para reduzir os danos, comunicar os responsáveis e iniciar a recuperação dos serviços.

Uma atualização do servidor Apache pode afetar APIs e o banco sofreu uma falha. Organize um plano de atualização segura, backup e recuperação.
Primeiro, realizar um backup completo do banco de dados e testar sua restauração. Depois, testar a atualização do Apache em ambiente de homologação para verificar se as APIs continuam funcionando. Após confirmar que está tudo certo, aplicar a atualização no servidor de produção. Caso aconteça algum problema, utilizar o backup para recuperar os dados e restaurar os serviços.

Semana 27Microsserviços e mensageria+

Qual framework estudado usa Python?
A) Flask.

Qual alternativa representa mensageria assíncrona?
A) RabbitMQ.

Kubernetes é utilizado para quê?
A) Orquestrar contêineres.

Explique o papel das rotas e dos testes no Flask.
As rotas definem os endpoints e os métodos HTTP da aplicação. Funções intermediárias podem verificar acessos, registrar logs e ajustar respostas. Os testes de unidade verificam partes isoladas do sistema e ajudam a identificar regressões.

Compare uma aplicação monolítica com microsserviços.
Na aplicação monolítica, todas as funcionalidades ficam reunidas em um único sistema. Já nos microsserviços, as funcionalidades são distribuídas entre serviços independentes com responsabilidades próprias, o que facilita a evolução e a escalabilidade individual, embora aumente a complexidade da comunicação.

Quando a comunicação assíncrona pode ser vantajosa?
Quando o sistema precisa trocar mensagens em segundo plano por meio de filas e mensageria, evitando travar o fluxo principal e melhorando o desempenho em cenários de alta demanda.

Um e-commerce com microsserviços enfrenta lentidão no processamento de pedidos. Sugira uma estratégia de comunicação e orquestração e justifique.
Adotar a mensageria assíncrona com RabbitMQ ou Kafka para processar os pedidos em filas sem travar a aplicação principal. Utilizar Kubernetes ou Docker Swarm para orquestrar os contêineres e escalar os serviços conforme a demanda, complementando com um service mesh para melhorar a comunicação e a observabilidade.

Semana 28Testes de integração e carga+

Testes de integração avaliam o quê?
A) A interação entre componentes e serviços.

Qual ferramenta é voltada a testes de carga?
A) k6.

Qual indicador ajuda a avaliar desempenho?
A) Tempo de resposta e taxa de erro.

Diferencie testes unitários, de integração e de carga.
Os testes unitários verificam componentes isolados do sistema. Os testes de integração avaliam a comunicação entre diferentes partes do sistema e serviços externos. Já os testes de carga analisam o comportamento da aplicação sob alta demanda, simulando muitos usuários ou requisições simultâneas.

Descreva um teste de sucesso e outro de erro para uma API de pagamentos.
Um teste de sucesso valida se, ao enviar dados válidos, a API processa a transação e retorna o status HTTP correto com os dados consistentes. Um teste de erro pode simular falhas como ausência de parâmetros obrigatórios, erro de autenticação ou cartão inválido para verificar se a API trata a exceção adequadamente.

Por que status HTTP 200, isoladamente, não comprova que a integração está correta?
Porque um código 200 indica sucesso no protocolo HTTP, mas a resposta pode trazer um corpo incorreto, dados inconsistentes, mensagens de erro internas ou um tempo de resposta inadequado.

Uma API de faturas precisa atender 500 usuários simultâneos. Planeje um teste de 15 minutos, definindo métricas, critérios de aceitação e relatório.
Planejar um teste de carga de 15 minutos utilizando JMeter, k6 ou Artillery para simular gradualmente até 500 usuários simultâneos acessando a API de faturas. Monitorar latência, taxa de erros, consumo de CPU e memória e estabilidade. O tempo de resposta médio deve ficar abaixo de um limite aceitável e a taxa de erros abaixo do limite definido, por exemplo 1%. O relatório sintetizará o comportamento sob carga, os gargalos e a estabilidade das respostas.
