Modelagem e Desenvolvimento de Banco de Dados

Semana 22Modelos SQL e NoSQL+

Aula 1

A melhor solução para uma loja virtual que está crescendo rápido é usar diferentes tipos de bancos de dados. Assim, cada parte do sistema pode usar o banco que funciona melhor para ela, levando em conta a velocidade, a segurança e o custo. Usar apenas um tipo de banco para tudo pode acabar causando problemas ou deixando o site lento.

Para guardar informações importantes, como os dados dos clientes, os pagamentos e os pedidos, o ideal é usar um banco de dados relacional, como o MySQL ou o PostgreSQL. Esse tipo de banco ajuda a manter os dados organizados e seguros, evitando problemas como cobrar duas vezes pelo mesmo pedido ou vender um produto que não tem mais no estoque.

Para guardar as informações dos produtos, uma boa opção é o MongoDB, que é um banco de dados NoSQL. Ele é útil porque cada produto pode ter informações diferentes. Por exemplo, uma roupa tem tamanho e cor, enquanto um computador tem memória e processador. Dessa forma, fica mais fácil adicionar e alterar informações dos produtos.

Para guardar o histórico de navegação e as ações dos usuários, podem ser usados bancos como Cassandra ou InfluxDB. Eles conseguem armazenar muitas informações e ajudam a evitar que o banco principal fique lento.

Já para cuidar do carrinho de compras e das sessões dos usuários, uma boa opção é o Redis. Ele guarda informações na memória do computador, permitindo que os dados sejam acessados rapidamente e deixando a navegação mais rápida.

Com essa divisão, a empresa consegue organizar melhor o sistema, manter os pagamentos seguros, atualizar os produtos com facilidade e atender muitos usuários sem precisar gastar tanto dinheiro.

Aula 2

Vantagens e desvantagens do SQL

Vantagens:

Mantém os dados corretos e seguros (ACID): Se acontecer algum erro durante uma operação, o banco pode desfazer o que foi feito. Assim, evita problemas como cobrar o cliente sem reservar o produto.

Evita erros entre os dados: Impede, por exemplo, que um pedido seja registrado para um cliente que não existe no sistema.

Desvantagens:

É mais difícil mudar a estrutura: Se a empresa quiser adicionar uma nova informação a uma tabela, como a voltagem de um produto, pode ser necessário fazer várias mudanças no banco.

Pode ficar lento em consultas mais complicadas: Para mostrar todas as informações de uma compra, o sistema pode precisar juntar várias tabelas (JOINs). Quando muitas pessoas acessam o site ao mesmo tempo, isso pode deixar as consultas mais demoradas.

Vantagens e desvantagens do NoSQL

Vantagens:

Busca rápida de informações: Como várias informações do pedido podem ficar guardadas juntas, o sistema consegue encontrar os dados com menos consultas.

Mais facilidade para fazer mudanças: Cada produto pode ter informações diferentes, sem precisar mudar toda a estrutura do banco de dados.

Desvantagens:

Pode repetir informações: O preço de um produto pode aparecer novamente no histórico do pedido. Isso é importante para guardar o valor que ele tinha no momento da compra.

Pode haver um pequeno atraso nas atualizações: Quando os dados são copiados para vários servidores, pode levar alguns milissegundos até que todos tenham as mesmas informações.

Qual é a melhor opção para a TechMarket?

Como a TechMarket está crescendo rápido, o melhor é usar SQL e NoSQL juntos, aproveitando as vantagens de cada um.

Onde usar SQL: Na parte financeira, nos pagamentos e no controle do estoque. Ele ajuda a manter os valores, os pedidos e os cadastros corretos, evitando erros e informações repetidas.

Onde usar NoSQL: Na lista de produtos e nas páginas de busca. Como muitas pessoas podem entrar na loja ao mesmo tempo, esse banco facilita o aumento da capacidade do sistema com mais servidores. Isso ajuda a evitar lentidão, principalmente em datas como a Black Friday.

Aula 3

Qual banco de dados NoSQL é mais indicado?

Para uma rede social como a DataConnect, uma boa opção é usar um banco de dados de grafos, junto com um banco de documentos, como o MongoDB, para guardar publicações e comentários.

Estrutura dos dados: Em uma rede social, os usuários, as publicações e as fotos são os nós. Já as amizades, curtidas e os compartilhamentos são as ligações entre eles. O banco de grafos ajuda a organizar essas conexões.

Consultas: Em um banco relacional, encontrar amigos de amigos que curtiram uma publicação pode exigir várias junções de tabelas (JOINs). Já o banco de grafos facilita esse tipo de busca e pode encontrar os resultados mais rapidamente.

Crescimento do sistema: Os bancos de documentos e de grafos permitem distribuir os dados entre vários servidores. Assim, fica mais fácil atender um número maior de usuários.

O que é uma arquitetura distribuída?

Uma arquitetura distribuída acontece quando os dados ficam divididos entre vários servidores que se comunicam pela rede, em vez de ficarem em apenas um servidor.

Por que isso é importante para a DataConnect?

Evita que o sistema pare completamente: Se um servidor parar de funcionar, os outros podem continuar atendendo aos usuários.

Divide o trabalho: As mensagens, curtidas e outras ações são distribuídas entre vários servidores. Assim, nenhum deles fica responsável por fazer tudo sozinho.

Como funciona a replicação e por que ela é importante?

A replicação acontece quando os mesmos dados são copiados para diferentes servidores. Ela pode funcionar de duas formas. No modelo líder e seguidor, um servidor recebe as alterações e depois as copia para os outros. No modelo sem líder, diferentes servidores podem receber alterações.

Por que isso é importante para a DataConnect?

Mantém a rede funcionando: Se o servidor principal apresentar algum problema, outro servidor com uma cópia dos dados pode assumir sua função.

Melhora a velocidade das consultas: Usuários de diferentes lugares podem acessar um servidor mais próximo, diminuindo o tempo de carregamento das informações.

##### O que é escalabilidade horizontal?

Escalabilidade horizontal é aumentar a capacidade do sistema adicionando mais servidores, em vez de trocar o servidor atual por um mais potente.

Vantagens para a DataConnect:

Crescimento com menos gastos: A empresa pode adicionar servidores conforme o número de usuários aumenta, sem precisar comprar equipamentos muito caros.

Facilidade para lidar com muitos acessos: Se muitas pessoas entrarem na rede social ao mesmo tempo, a equipe pode adicionar servidores para ajudar a atender todos. Depois, pode retirar os servidores extras quando não forem mais necessários.

Plano básico de implementação para a DataConnect

 Escolha do banco de dados

Tecnologias escolhidas: MongoDB para guardar publicações, comentários e perfis dos usuários, junto com o Neo4j para organizar as amizades e sugerir novos contatos.

Como isso ajuda: As publicações e os comentários podem mudar com o tempo, como quando é necessário adicionar um novo tipo de foto ou vídeo. O MongoDB facilita essas mudanças. Já o Neo4j ajuda a encontrar conexões entre os usuários e sugerir amigos.

Estratégia de replicação

Tipo escolhido: Replicação assíncrona usando um conjunto de cópias dos dados (Replica Set).

Justificativa: Em uma rede social, é importante que as ações aconteçam rapidamente. Quando alguém clica em “curtir”, o servidor principal registra a ação e o aplicativo continua funcionando. Depois, a alteração é copiada para os outros servidores.

Isso deixa o uso mais rápido, mas pode acontecer um pequeno atraso até que outros usuários consigam ver a curtida.

Como aumentar a capacidade do sistema

Estratégia escolhida: Divisão dos dados em partes, chamada de Sharding.

Como será feita: Os dados dos usuários serão divididos entre diferentes grupos de servidores. Essa divisão pode ser feita pelo número de identificação do usuário ou pela região onde ele está.

Por exemplo, os usuários da América Latina podem ser atendidos por um grupo de servidores, enquanto os da Europa são atendidos por outro. Um sistema direciona cada acesso para o servidor correto. Assim, a rede social consegue crescer e atender mais pessoas.

Aula 4

Banco de dados de documentos

Explique por que um banco de dados de documentos, como o MongoDB, é adequado para essa situação.

O MongoDB é uma boa opção para guardar os produtos porque permite armazenar informações diferentes para cada um e facilita a busca dos dados.

Estrutura flexível: Cada produto pode ter suas próprias informações. Por exemplo, roupas precisam de tamanho e cor, enquanto produtos eletrônicos podem precisar da voltagem. O formato JSON permite guardar essas informações sem exigir que todos os produtos tenham os mesmos campos.

Informações no mesmo lugar: Os comentários dos usuários podem ficar guardados junto com as informações do próprio produto. Assim, o sistema não precisa buscar os dados em várias tabelas, facilitando o carregamento da página.

Facilidade para fazer mudanças: Se a ShopWorld quiser adicionar novas informações, como peso ou tamanho do produto, poderá fazer isso sem precisar mudar todos os registros antigos ou parar o banco de dados.

Banco de dados chave-valor

Explique por que um banco de dados chave-valor, como o Redis, é adequado para essa situação.

O Redis é uma boa opção para cuidar do carrinho de compras porque permite encontrar e atualizar informações rapidamente.

Velocidade na memória: O carrinho de compras muda o tempo todo. O Redis usa a memória RAM para guardar e acessar informações com rapidez.

Busca direta pela chave: O sistema não precisa fazer buscas complicadas. Ele procura uma chave única, como “carrinho_usuario_1001”, e encontra a lista de produtos e suas quantidades.

Controle do tempo de armazenamento: É possível definir um tempo para os dados serem apagados automaticamente. Se o usuário abandonar o site, o carrinho poderá ser apagado depois de um período, ajudando a economizar memória.

Banco de dados de grafos

Explique por que um banco de dados de grafos, como o Neo4j, é ideal para esse tipo de estrutura.

O Neo4j é uma boa opção para organizar a rede de parceiros porque facilita a busca pelas ligações entre empresas, fornecedores e transportadoras.

Ligações entre os dados: É importante saber quais empresas trabalham juntas. No banco de grafos, ligações como “FORNECE” e “PARCEIRO_COMERCIAL” ficam registradas junto com os dados das empresas. Isso facilita encontrar as informações.

Buscas rápidas: Por exemplo, o sistema pode descobrir quais transportadoras trabalham com os fornecedores de uma determinada camiseta. O banco de grafos facilita essa busca, enquanto um banco relacional pode precisar juntar várias tabelas (JOINs).

Organização fácil de entender: A estrutura de nós e ligações mostra como as empresas, os fornecedores e as transportadoras se relacionam na ShopWorld. Isso facilita o trabalho da equipe de tecnologia na criação e na manutenção do sistema.

Semana 25Sharding e balanceamento+

Aula 2

Como adicionar novos shards ao cluster?
Para adicionar shards, é preciso configurar um servidor MongoDB novo e conectá-lo ao cluster, usando o comando sh.addShard(). Assim o cluster vai poder utilizar o novo servidor.

O que acontece se um shard falhar?
Parte dos dados pode ficar temporariamente indisponível. Porém, se houver réplicas configuradas, outro servidor poderá assumir seu lugar, evitando a perda de dados e mantendo o sistema funcionando.

Como o MongoDB redistribui os dados ao adicionar shards?
O MongoDB utiliza um balancer (balanceador), que distribui os dados entre os shards para evitar que apenas um servidor fique sobrecarregado. Dessa forma, os dados ficam mais bem distribuídos e o sistema consegue trabalhar com mais eficiência.

Semana 26Backup e recuperação+

Aula 2

Qual é a diferença entre os tipos de backup realizados?
O backup completo realiza a cópia de segurança de todos os bancos de dados e coleções presentes na instância do MongoDB, salvando o estado global do sistema. Já o backup incremental simulado concentra-se apenas em partes específicas ou coleções que sofreram alterações recentes (como a coleção orders), otimizando o tempo de processamento e o espaço de armazenamento necessário.

Por que é importante simular falhas durante os testes de recuperação?
Simular falhas (como a exclusão intencional de um banco de dados) é fundamental para validar se o plano de recuperação é realmente eficaz e se os procedimentos de restauração funcionam sem erros na prática, garantindo que a equipe saiba exatamente como agir em uma situação de emergência real sem comprometer a integridade dos dados.

Que benefícios a automação de backups pode trazer para uma empresa?
A automação de backups reduz drasticamente o risco de falhas humanas ou esquecimentos, assegurando que cópias de segurança atualizadas sejam geradas de forma consistente e periódica (como diariamente), garantindo maior conformidade, segurança da informação e continuidade dos negócios.

Como vocês verificariam a integridade de backups realizados periodicamente?
A integridade dos backups pode ser verificada realizando testes periódicos de restauração em um ambiente de homologação ou teste isolado, conferindo se os arquivos gerados não estão corrompidos, validando o log de execução das ferramentas e executando consultas de contagem de registros e amostragem de dados para confirmar que as informações restauradas correspondem perfeitamente à realidade da base de produção.
